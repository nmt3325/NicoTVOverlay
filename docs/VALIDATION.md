## 0.1.4の実機再検証 — 番組表からの復帰と局追従

2026-09-09 JST、実装commit `7d17c2d441fec9810b9f1e26d70a5ccdc99ada18`（versionName 0.1.4 / versionCode 5）。単体テストは390件で失敗0・skip0。GitHub Actions run 34309209862 のdebug APKを、証明書SHA-256が上記の開発用証明書と一致することを確認した上でAQUOS 4KTVJ25-2（Android 14）へインストールし、Tailscale経由のADBで計測した。

台本は「全画面ライブ → 番組表 → BACK → CHANNEL_UP → 番組表 → BACK」。検出サービスとオーバーレイのdumpsysを0.7〜1.0秒間隔で採取した。

0.1.3では番組表からBACKで戻ったあと12秒以上`station=null`のままで、コメントが再開しなかった。0.1.4では理由表示が`OSDが出ないため直前の局を暫定復元`となり、上表のとおり約4秒で局が戻る。jk1では`connection=LIVE`で受信と描画も再開した。選局した直後は新しい局のOSDを`校正済み局ラベルで確認`しており、古い局を暫定復元で描き戻すことはなかった。

暫定復元は次をすべて満たすときだけ働く。全画面ライブの静かな観測が2.5秒連続すること、直前の確定局が90秒以内であること、前面アプリが同一であること、確認待ちの選局がないこと。選局キーを受けたとき、および校正済みだが未登録の局ラベルを読んだときは記憶を破棄する。既存のfail-closed不変条件は弱めずに維持し、`DetectionPolicyTest`と`AquosOsdTest`で固定した。

jk2の`received=0`は放送局側の投稿量による。同日の別計測では80秒あたりjk1が83件、jk5が13件、jk4が0件で、受信数はチャンネルの賑わいに依存する。

この節で確認できたのはAQUOS 4KTVJ25-2・Android 14・地上波の全画面ライブに限る。他メーカー、他の放送アプリ、全エイリアスの実機確認、画素単位でのコメント描画の証明は未検証のまま。

同じAPKで「他アプリへの離脱」と連続運転も測った。HOMEでテレビアプリを隠した12秒間は`テレビアプリが前面にありません`として検出を解除し、オーバーレイもIDLEで描画しなかった。暫定復元は前面アプリが違う間は働かない。テレビアプリへ戻ると約4秒で`校正済み局ラベルで確認`としてjk1を再取得し、その後60秒の連続観測では検出局がjk1のまま安定し、受信件数0→5件、描画フレームは1921まで増えた。計測ログは開発用ワークスペース内に保管している。
